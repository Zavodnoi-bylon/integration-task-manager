# Team Activity Explorer

Отдельный дашборд активности отдела: задачи из обычных Telegram-переписок,
уведомлений Asana и других источников с подтверждающими сообщениями.

23 октября 2026 исходники действующего VPS собраны в единый локальный Git-проект
для PyCharm и Codex. Переезд на новый сервер ещё не выполнен.
Оформление основано на TheRaw; модель задач, API, импорт и графики написаны заново.

**Начать здесь:** [единый контекст двух чатов](PROJECT_HANDOFF.md), [рабочий флоу](docs/WORKFLOW.md),
[проверенное состояние](docs/STATUS.md), [план переезда](docs/MIGRATION.md),
[PyCharm и доступ Codex](docs/LOCAL_DEVELOPMENT.md).

## Что здесь уже есть

- График поступивших и завершённых задач по дням / неделям.
- Отдельная линия **«Известно открытых»** на конец периода.
- Медиана календарного времени от подтверждённого запроса до завершения.
- Фильтры типа задачи, клиента, известного ответственного и текстовый поиск.
- Реестр с пагинацией, CSV всего выбранного среза и переходом с графика к задачам.
- Карточка с историей событий и сообщениями, подтверждающими выводы.
- Очередь предложений ИИ, которые ещё не включены в статистику.
- Нормализация Telegram Desktop JSON, сохранение версий сообщений, защита от повторного импорта.
- Явная проверка и принятие задач через CLI с журналом изменений.
- PostgreSQL со своими схемами, volume, сетью и ролями reader/writer/admin.

**Дашборд работает на старом VPS; полная ежедневная цепочка ещё не завершена.**
Telegram-клиент перенесён в `collector/`; его расписание и состояние описаны в STATUS.
Нет сетевого Asana-коллектора, вызова модели ИИ или браузерного редактора задач.
Смысловой анализ Codex запускается пользователем вручную из локального приложения.
В стандартном Compose доступ к UI ограничен localhost VPS и SSH-туннелем.
Встроенные примеры вымышлены и не являются отчётом отдела.

## Как читать показатели

| Показатель | Значение |
|---|---|
| Поступило | Уникальные задачи с первым известным событием `requested` в периоде |
| Завершено | Уникальные задачи с подтверждённым допустимым `completed` в периоде |
| События завершения | Отдельный счётчик, учитывающий повторное завершение после `reopened` |
| Известно открытых | Остаток наблюдаемых незакрытых задач на конец периода, включая задачи до начала периода |
| Срок решения | Календарный интервал от известного первого запроса до завершения; ожидание входит в интервал |
| Ответственный | Только явно подтверждённое имя; неизвестный остаётся неизвестным |

Остатки не складываются по дням. Недельное число уникальных завершённых задач
также не равно сумме дневных значений, если одна задача переоткрывалась.
Смены и общий Telegram-аккаунт не используются для догадок об исполнителе.
Процент занятости и трудозатраты по этой модели не вычисляются.
Подробные правила: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Быстро посмотреть локально — вымышленные данные

Нужны Python 3.12 и Node 24. Команды ниже выполняются в новом каталоге проекта,
не в исходных проектах с VPS.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
npm ci
npm run dev:demo
```

Открыть `http://127.0.0.1:4173/`. Команда запускает API и Vite под одним процессом.
Завершение — Ctrl+C. В интерфейсе постоянно виден баннер
«Демонстрационные данные — не отчёт отдела».
Режим включается только явной переменной `ACTIVITY_DEMO=1` в dev launcher.
В стандартном Compose задано `ACTIVITY_DEMO=0`; при отсутствии БД приложение
сообщает об ошибке, а не подставляет примерные цифры.

PowerShell: создать окружение через `py -3.12 -m venv .venv`, затем использовать
`.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock` и те же npm-команды.
Не переносить `.venv` между Windows и Linux.

## Проверить настоящий экспорт без БД и сети

```bash
.venv/bin/python sync.py ingest-messages /path/to/chat.json --dry-run
.venv/bin/python sync.py normalize /path/to/chat.json --output /path/to/normalized.json
```

Вывод dry-run содержит только счётчики, без текста сообщений.
Нормализованный файл содержит исходный текст и должен храниться как рабочие данные,
а не попадать в Git. Если в экспорте нет Unix-времени, необходимо явно указать
`--timezone Europe/Moscow` (либо настоящий часовой пояс экспорта).
Наличие timezone в строке не заменяет это явное решение для fallback-режима.

## Из сообщений в проверенные задачи

1. Нормализовать экспорт и импортировать сообщения в новую БД.
2. Передать ИИ нужные сообщения с устойчивыми ID и revision hash;
   использовать [docs/EXTRACTION_PROMPT.md](docs/EXTRACTION_PROMPT.md).
3. Получить JSON по `examples/task-proposals.schema.json`.
4. Проверить файл: `sync.py ingest-proposals tasks.json --dry-run --messages normalized.json`.
   Без `--messages` dry-run проверяет только синтаксис и прямо сообщает `syntax_only`.
5. Импортировать предложения. Они попадут в очередь и не изменят показатели.
6. Проверить доказательства и выполнить явный `review --decision accept`.

Для исправления уже принятой задачи передаётся полный новый снимок её событий
и подтверждений, а также ожидаемая текущая revision. Старое решение сохраняется
в журнале. `--actor` — введённая оператором подпись, не установленная автоматически
персональная учётная запись. Веб-интерфейс только читает; кнопок записи нет.

## Сборка и тесты

```bash
npm run build
.venv/bin/python -m unittest discover -s tests -v
node tests/frontend.test.mjs
```

Все зависимости зафиксированы в `package-lock.json`, `requirements.lock`
и `requirements-dev.lock`. Dockerfile использует production lock, `npm ci`
и непривилегированного пользователя 10001. Образы Docker закреплены по версиям
семейства, но пока не по digest: перед production-запуском нужно зафиксировать
и проверить фактически полученные образы. Это не было выполнено в среде без Docker.

## Установка на VPS

Для нового сервера использовать [docs/MIGRATION.md](docs/MIGRATION.md).
[docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) сохраняет историческую инструкцию первичного пилота,
а не актуальный сценарий переноса существующей базы.
Не запускать установщики из исходного TheRaw: они обращаются к существующему
Vaultwarden/Caddy, копируют AIO-токен и меняют текущую конфигурацию сервера.
