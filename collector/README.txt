Сбор активности Telegram — обслуживание

Это инструкция старого развёрнутого collector, сохранённая для обслуживания.
Целевой процесс и ограничения переноса: ../docs/WORKFLOW.md и ../docs/MIGRATION.md.
Не запускать install.sh на новом сервере без адаптации: он возвращает прежнее
15-минутное расписание. Суточные пакеты и два аккаунта пока не реализованы.

Установка на VPS: /home/vaultadmin/team-activity-ingest
Python: .venv/bin/python. Код текущей версии: current/ (ссылка на releases/).
Существующие Vaultwarden, TheRaw Analytics, Asana Alerts не используются.

Поток данных
Telegram user account -> Telethon -> SQLite -> data/normalized/messages.json.
Telegram Desktop JSON -> data/inbox/*.json -> та же SQLite и тот же JSON.
Cron запускает current/run.sh каждые 15 минут независимо от SSH и перезагрузок.
До авторизации работает только импорт. Первый сбор читает всю доступную историю
только чатов из targets.json; затем новые сообщения и последние 1000 ID для правок.
Никакие сообщения не отправляются. Автоматического вступления в чаты нет.
При большом чате первый проход может занять время; checkpoint сохраняется пачками.

Первый вход (единственная интерактивная операция)
Из Windows PowerShell:
ssh -t -F "C:\Users\Судак\.ssh\config" vaultwarden /home/vaultadmin/team-activity-ingest/current/setup-telegram.sh
Скрипт спрашивает API ID, API hash, номер, код и при необходимости пароль 2FA.
Секреты вводятся скрыто непосредственно на сервере. В переписку их не передавать.
API ID/hash получают для своего приложения на https://my.telegram.org/apps.
Разрешённые чаты задаются приватной конфигурацией, не исходниками Git.
После входа запускается первый сбор; расписание уже установлено.
Следующие входы используют отдельную Telethon-сессию этого проекта.

Формат отчётности
data/normalized/messages.json: schema_version, generated_at, message_count, messages.
Каждое сообщение содержит source_key, chat, message_id, sent_at, original_date,
edited_at, sender.id, sender.name, reply_to_message_id, text.
source_key = telegram:<signed chat id>:<message id> — ключ для обновления отчёта.
Текст собирается из всех частей, обрезаются только внешние пробелы.
Служебные события и сообщения без текста исключаются, подписи к медиа остаются.
Время с Unix timestamp переводится в UTC; если Desktop оставил только местное
время без зоны, оно сохраняется без приписывания выдуманного часового пояса.
Имена и текст не маскируются эвристиками. JSON содержит рабочую переписку.
Одинаковые файлы пропускаются по SHA-256, сообщения объединяются по source_key.
Более старые версии не затирают более новые по времени отправки/редактирования.
SQLite — основной источник данных; JSON заменяется атомарно после успешного запуска.

Обычная работа
Новые экспорты можно класть в data/inbox под любым именем с расширением .json.
Загружать сначала как .upload, затем переименовывать в .json после окончания передачи.
Исходные экспорты остаются в inbox, но повторно не импортируются. Очистка вручную
допустима после проверки импорта и резервной копии; программа их не удаляет.
Не класть туда нормализованный JSON или облачный task-ready JSON.
Для добавления чатов изменить только chats в config.json, а не код; usernames
или числовые signed ID. Аккаунт должен уже иметь доступ. Секреты файла сохранить.
Безопасный повторный импорт исходников для обновления нормализатора потребует
новой версии схемы/миграции; текущая версия по умолчанию не переигрывает ledger.

Проверка (на сервере)
ACTIVITY_HOME=$HOME/team-activity-ingest $HOME/team-activity-ingest/.venv/bin/python $HOME/team-activity-ingest/current/ingest.py status
tail -n 30 $HOME/team-activity-ingest/logs/ingest.log
crontab -l
data/status.json хранит последний завершённый запуск, data/error.json — последнюю
ошибку без текста переписки и секретов. Для свежести сверять время этих файлов.
Старый error.json после успешного запуска сохраняется как история последней ошибки.
Для немедленного запуска: $HOME/team-activity-ingest/current/run.sh
Одновременные процессы блокируются. Логи ротируются при достижении 1 МБ.

Резервирование и откат
Автоматически создаётся ежедневная согласованная SQLite-копия после успешного
сбора/импорта, хранятся последние 14. Копии лежат в backups/daily-*.sqlite3.
Это локальные копии на том же VPS, а не защита от потери самого сервера.
config.json и data/session содержат секреты; автоматические бэкапы их не копируют.
В случае потери сессии можно пройти setup заново. Для переноса их нужно копировать
отдельно защищённым способом; при компрометации отозвать сессию в Telegram.
До развёртывания сохраняется crontab и путь предыдущего релиза в backups/.
Откат кода: остановить ТОЛЬКО свой блок cron, дождаться текущего запуска, вернуть
current на путь из previous-release-*.txt, затем вернуть свой блок cron.
Восстановление данных: остановить свой cron и дождаться завершения процесса,
сохранить всю data, убрать activity.sqlite3, activity.sqlite3-wal и -shm в отдельный
каталог, скопировать выбранный daily-*.sqlite3 как data/activity.sqlite3.
При восстановлении старой БД повторно возможен безопасный сбор из checkpoint;
восстановить inbox, если нужен повторный импорт отсутствующих экспортов.

Ограничения
Удаления сообщений в Telegram не отслеживаются; недоступные аккаунту данные
не извлекаются. Правки старше последних 1000 ID автоматически не перечитываются.
Для полного перечитывания чата: остановить собственное расписание, сделать backup,
удалить только строку соответствующего chat_id из таблицы cursors, затем запустить.
Отозванная сессия, FloodWait дольше минуты, отсутствие доступа или сетевые ошибки
дают ненулевой код завершения; cron попробует снова через 15 минут. Уведомления
об ошибках во внешние сервисы не настроены. Отчёты должны проверять свежесть JSON.
Извлечение задач и итоговые отчёты строятся поверх этих данных отдельно.

Пять тестов: старый отбор и метаданные; повторы и правки; откат ошибочного импорта;
ID чатов/checkpoint; восстановление сбора после обрыва с сохранённой пачкой.

сообщениях предоставленного экспорта (всего в исходнике 135 событий).
