# Воспроизводимая SQL-проверка на вымышленных данных

Эта проверка предназначена только для локальной разработки. Она поднимает новую
PGlite БД **в памяти**, слушающую **127.0.0.1:55432**, и не использует `.env`,
Vaultwarden, сервер VPS, реальные чаты, реальные пароли или существующие БД.
Папка не нужна работающему приложению и не входит в его runtime-зависимости.

## Запуск

Из корня проекта, с установленными Python-зависимостями проекта и Node.js:

```bash
npm install --prefix tests/integration --ignore-scripts --no-audit --no-fund
node tests/integration/server.mjs
```

Дождитесь строки `pglite_ready`. Во втором терминале:

```bash
.venv/bin/python tests/integration/check_roundtrip.py
```

На Windows используйте Python из активированной virtualenv. Скрипт использует
реальный `psycopg` и PostgreSQL wire protocol. В конце выводятся имена выполненных
проверок и `count: 28`. После проверки остановите Node-процесс через Ctrl+C.
Для повторного запуска нужна **новая** memory DB: перезапустите Node-сервер.

Сервер создаёт только тестовые роли `activity_reader`/`activity_writer` и применяет
настоящий `init/10-schema.sql`. Из подаваемой строки удаляется единственная
psql-директива `\set ON_ERROR_STOP on`; production SQL-файл не изменяется.

## Что проверяется

- Импорт сообщений, hash файла, перекрывающиеся экспорты и отсутствие дублей.
- Новая/старая редакции, конфликт разных текстов при одинаковом времени.
- Несогласованная трактовка timezone при повторном импорте.
- Импорт proposals без автоматического принятия, существование evidence.
- Accept, сохранение ручного решения при новом proposal, stale revision rollback.
- Явная очистка исполнителя через `null`, reopening с сохранением истории.
- Reject без удаления старой задачи, журнал before/after.
- Атомарный отказ при отсутствующем evidence и фиксация failed import.
- SELECT-права reader и запрет его записей; запрет writer изменять raw-редакции
  сообщений или содержимое proposals, удалять задачи или менять review-log;
  составной FK между event и task. Для proposals writer может менять только `state`.

## Точные границы проверки

Проверено на **PGlite 0.5.11, PostgreSQL 18.6 (WASM)**, `psycopg 3.2.9`.
Это не запуск Docker-стека и не подтверждение совместимости развёртывания с
PostgreSQL 16. Нативный PG16 остаётся отдельной проверкой перед запуском на VPS.

Права проверяются через `SET ROLE`, поскольку тестовый socket-server не проверяет
пользовательские пароли как production Postgres. Здесь не проверяются секреты,
аутентификация контейнеров, TLS, Caddy, сеть Compose, расписание, живые collectors,
backup/restore или несколько конкурирующих соединений. PGlite имеет другую модель
конкурентности; успешный advisory-lock вызов не доказывает корректность конкуренции
в production. Бизнес-содержимое evidence не оценивается моделью или тестом.

Пакеты/состояние `node_modules` и любые файлы базы в исходный архив не включаются.

Первичные сведения о тестовом runtime: [PGlite Socket](https://pglite.dev/docs/pglite-socket).
