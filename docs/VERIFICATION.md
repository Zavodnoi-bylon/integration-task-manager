# Что проверено — 22 октября 2026 года

## Результат

Подготовлен отдельный локальный проект `team-activity-explorer`. Исходный ZIP
и все 34 распакованных файла AIO/TheRaw побайтово совпадают с исходными SHA-256.
`src/base.css` нового проекта побайтово совпадает с CSS TheRaw. Изменения на VPS,
sudo-команды, обращения к Telegram/Asana API и вызовы внешней модели не выполнялись.

| Зависимости Python | `pip-audit`: No known vulnerabilities found | Аналогично, для зафиксированного локального набора |

SQL-проверки проводились на **PGlite 0.5.11 / PostgreSQL 18.6 WASM**, через
реальный psycopg wire protocol, с вымышленными данными. Это проверка SQL-логики
и прав, но не эквивалент native PostgreSQL 16 в целевом Docker-окружении.
Временные тестовые БД после проверок остановлены.

В среде выполнения сетевой sandbox блокировал socketpair, используемый TestClient.
API-тесты выполнены в разрешённом режиме выполнения; обращения к рабочему VPS
для этого не потребовались. Docker в среде аудита отсутствует.

Команды воспроизведения обычных тестов:

```bash
.venv/bin/python -m unittest discover -s tests -v
node tests/frontend.test.mjs
npm run build
npm audit
```

Отдельная инструкция SQL-проверок — `tests/integration/README.md`.

## Проверка в браузере

Использован локальный demo launcher с **24 вымышленными задачами**, тремя
ожидающими предложениями и постоянной отметкой «не отчёт отдела».

Проверены:

- Переключение дней и недель, включая неполные крайние недели.
- Столбцы поступивших/завершённых и линия известного открытого остатка.
- Переход со столбца завершений за 5–11 октября к шести соответствующим задачам.
- Карточка задачи с хронологией и тремя исходными сообщениями.
- Карточка ожидающего предложения с текстом подтверждения до принятия.
- Поиск без результатов: прочерки и объяснение отсутствия данных, без подмены нулями.
- Сброс фильтров и восстановление реестра.
- CSV, скачанный браузером: **24 строки данных, 10 колонок**, одинаковая ширина записей.
- Подписи крайних дат и размеры полос категорий после исправлений.

Снимок интерфейса поставляется отдельно. Все числа на нём демонстрационные.
Проверка выполнена в настольном браузере; полная матрица мобильных устройств,
клавиатурной доступности и экранных дикторов не проходилась.

## Реальные входные файлы

Оба предоставленных Telegram JSON прошли `ingest-messages --dry-run` без БД:
106 записей в рабочей переписке и 24 в файле уведомлений Asana.
Это проверка совместимости формата и нормализации, **не оценка количества задач
или качества извлечения ИИ**. Рабочие сообщения не перенесены в код, тесты,
скриншот или поставляемый архив. Подробнее — `IMPORT_VERIFICATION.md`.

## Что пока не проверено и не готово к автоматическому запуску

- Сборка Docker image и запуск Compose на native PostgreSQL 16.
- Потребление памяти/CPU, конкурирующая нагрузка и доступные ресурсы VPS.
- DNS, TLS, Caddy и публичная авторизация нового приложения.
- Backup/restore новой БД: подготовлены скрипт и команды, восстановление не выполнялось.
- Непрерывный сбор Telegram/Asana, обработка разрывов соединения и расписание загрузок.
- Внешний вызов модели, качество распознавания задач и связи «запрос–готово» на размеченной выборке.
- Персональная авторизация редактора: текущий web только читает; CLI `--actor` — подпись оператора.
- Миграция существующего volume: init предназначен для новой БД; дальнейшие версии потребуют миграций.
- Docker image digests: семейства версий выбраны, фактически полученные образы ещё не закреплены по digest.

Прошедшие тесты проверяют реализованные правила. Они не доказывают полноту
источников, правильность решения ИИ или готовность окружения на VPS.
Для пилота сначала нужна ручная сверка 30–50 реальных задач, затем отдельная
проверка контейнеров, прав и восстановления на целевом сервере.
