## Автоматические проверки

В `tests/test_ingest.py` и `tests/test_proposals.py` проходят 25 stdlib unittest:
идентичность сообщений, сохранение raw JSON/entities и ссылок, Unix timestamps,
явный fallback timezone, редакции и конфликты, неизменность исходного файла,
dry-run без БД, evidence, жизненный цикл, reopening, revision guard и явный `null`.
Все тестовые сообщения вымышлены и не скопированы из пользовательских файлов.

Отдельно выполнены 28 SQL-сценариев через реальный `psycopg` на новой локальной
PGlite memory DB. Объединённый воспроизводимый скрипт
`tests/integration/check_roundtrip.py` прошёл целиком на чистой БД. Проверены
настоящая DDL, транзакции, FK и эффективные права SQL-ролей; используются только
вымышленные записи. SQL runtime: PGlite 0.5.11 / PostgreSQL 18.6 WASM.

Дополнительно проверен реальный read-only repository и FastAPI для очереди review:
единственная pending-задача ссылалась только через `events[].evidence` на старую
редакцию сообщения, отсутствующую в `work.evidence`. До принятия API вернул именно
указанную старую редакцию, а не новый текст сообщения; канонических задач и
показателей выполненной работы не добавилось. Проверка использовала отдельную
свежую memory DB и вымышленные сообщения.

Проверка PostgreSQL 16 в Docker, работа VPS и живые подключения к Telegram/Asana
не выполнялись. Ограничения и команды воспроизведения перечислены в
`tests/integration/README.md`.

Пример task JSON даёт `syntax_only` без evidence bundle. Полное offline-сообщение
`evidence_verified: true` выдаётся только при совпадении всех точных ссылок с
переданным normalized bundle. При записи в БД все ссылки проверяются по БД,
а proposals остаются pending до отдельного `review`.
