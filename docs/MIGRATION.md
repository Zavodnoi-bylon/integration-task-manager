Docker/Compose и Python venv установлены, firewall включён, SSH-пароли отключены. Для финального snapshot остаётся согласованная остановка записи из последовательности ниже.

## Состав

| Что | Источник | Способ переноса |
|---|---|---|
| Dashboard + API + SQL + importer | Корень репозитория | Git, сборка Docker |
| Collector | `collector/` | Git, Linux venv либо отдельный контейнер после проверки |
| PostgreSQL activity | Старый Compose volume | Согласованный `pg_dump -Fc`, восстановление PostgreSQL 16 |
| Collector SQLite + inbox + checkpoint | Старый collector `data/` | Online SQLite backup или остановленный collector; не копировать живую БД без WAL |
| Конфигурация и Telegram-сессия | `config.json`, `data/session/` | Отдельный защищённый перенос либо новая интерактивная авторизация |
| Пароли БД | Старый `.env` | На новом хосте генерировать новые; роли создать отдельно |
| Октябрьские входные пакеты/доказательства | Dashboard `data/inbox` | Отдельная копия данных, вне Git |

## Последовательность

1. Получить IP, пользователя и проверенный SSH-доступ нового VPS. Создать отдельный alias `team-activity`, не перенаправлять старый `vaultwarden`. Закрепить host fingerprint после проверки у провайдера.
2. Выбрать приватный GitHub repository, проверить код на секреты, запушить и зафиксировать commit. PyCharm и Codex открывают один локальный checkout.
3. Проверить Docker/Compose, свободное место, архитектуру, время/NTP нового хоста. Не открывать PostgreSQL в Интернет. Для стартового UI достаточно SSH-туннеля.
4. Восстановить пробную копию БД. Перед финальной копией приостановить только запись этого проекта: collector schedule и ручные импорты; дождаться процессов. Зафиксировать timestamp, counts и checksums. Старый UI может продолжать читать.
5. Сделать полный custom-format dump БД без глобальных ролей/паролей; `pg_restore --list` проверяет структуру архива, но не заменяет пробное восстановление. Сохранить отдельную копию исходных данных collector и inbox. Секреты — отдельно с правами 0600, не в Git и не в логах.
6. На новом сервере развернуть код фиксированного commit. Создать новые пароли и роли через Compose init на **пустом** volume. Для пробного restore создать отдельную пустую БД; восстановить с `--no-owner --no-acl --exit-on-error --single-transaction`. Затем восстановить нужные GRANT для reader/writer согласно DDL и проверить эффективные права. Не импортировать полный schema dump поверх уже созданных одноимённых таблиц.
7. Для финального запуска согласовать отдельную пустую целевую БД/volume и выполнить проверенную процедуру. Проверить FK, сообщения/ревизии/tasks/events/evidence/review_log, контрольный отчёт, очередь и отсутствие демо. Восстановление только data-only в уже инициализированную БД требует отдельной проверки deferred FK и не принимается как универсальный рецепт.
8. Перенести collector state и выбранную сессию либо авторизовать рабочие аккаунты заново. Не запускать одну Telegram-сессию одновременно на двух машинах. На новом хосте включить одно суточное расписание 00:10 Europe/Moscow; старый installer пока возвращает 15-минутный cron и должен быть исправлен перед применением.
9. Доделать мост и дневные пакеты из `WORKFLOW.md`; выполнить один пакет через локальный Codex: чтение → evidence JSON → validation → импорт → API → processed. Проверить повтор того же пакета без дублей и восстановление после сбоя.
10. Переключить пользовательский SSH-туннель/домен только после проверки. Сохранить старую БД и копии для отката. Старый сборщик оставить выключенным, но данные не удалять. Определить внешний backup-приёмник и проверить восстановление: копия на том же VPS не защищает от потери VPS.

## Доступ Codex

Обычный SSH-пользователь владеет кодом и входными пакетами. Codex сам читает, загружает файлы и запускает разрешённый importer. Для этого можно использовать проектный writer из локального server venv без Docker socket; пароль хранится только на сервере. DB-порт при необходимости публикуется исключительно на `127.0.0.1` отдельным override.

Не выдавать Docker group или unrestricted passwordless sudo под видом «только доступ к проекту»: это практически root. Начальная установка Docker/ролей/firewall требует действий администратора; повседневная обработка пакетов должна обходиться без sudo. Права writer и путь запуска настроить и проверить на новом хосте.

## Приёмка

- Дамп действительно восстановлен; количество строк и контрольный API совпадают с финальным snapshot старого сервера.
- UI работает через выбранный доступ; БД не доступна из внешней сети.
- reader не может писать; рабочий importer пишет только в нужную БД.
- Два аккаунта/темы и 00:10 МСК проверены реальным запуском.
- Ручной анализ Codex не требует пересылать ZIP или копировать скрипты пользователем.
- Повтор пакета не создаёт дубли, ошибочный пакет не отмечается завершённым.
- GitHub не содержит переписок, паролей, сессий и дампов.
- Отдельный backup восстановлен в проверочную БД.

До выполнения этих пунктов перенос не считается завершённым.
