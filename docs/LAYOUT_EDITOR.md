# Настройка расположения блоков

Добавлено и выложено 23 октября 2026 в новый дашборд.

## Использование

1. Под заголовком «Работа команды» нажать «Настроить расположение».
2. Перетаскивать блок за появившийся заголовок с ручкой ⠿.
3. Для изменения ширины/высоты тянуть нижний правый угол. Ширину можно также
   выбрать в процентах рядом с заголовком; «Авто» возвращает высоту по содержимому.
4. «Сохранить» записывает изменения. «Отмена» возвращает последнюю сохранённую раскладку.
5. «Исходный вид» восстанавливает стандартную компоновку в режиме предпросмотра;
   для её применения тоже нужно нажать «Сохранить».

Настраиваются шесть блоков: основные показатели, поток задач, известно открытых,
структура работы, реестр с предложениями, календарь. Фильтры и заголовок остаются
над ними. Сетка размещает блоки без перекрытия, размеры ограничены для читаемости.
Высота — минимальная: содержимое не обрезается, при необходимости блок выше выбранного
размера. Календарь по умолчанию остаётся компактным и без постоянно видимых имён.

На узких экранах блоки идут одной колонкой, порядок сохраняется; выбранные ширины
снова применяются на широком экране. Календарь на узком экране не шире 360px.
Для клавиатуры: фокус на ручке перемещения и ↑/↓ меняют порядок; стрелки на ручке
размера меняют ширину/высоту.

## Общая раскладка и права

Раскладка хранится на сервере и применяется у всех при открытии или обновлении страницы.
Прежний localStorage больше не определяет расположение. 23 октября перенесён текущий
вид владельца: calendar 3 колонки, metrics 9/минимальная высота 168px, flow 7,
backlog 5, categories 12, registry 12.

Редактор доступен только администратору. «Сохранить» меняет общую раскладку;
viewer и tech lead не могут менять её даже прямым запросом к API. Для tech lead
из общей раскладки берутся только разрешённые панели с сохранением порядка и размеров.
До сохранения изменения временные. При ошибке сервера редактор сообщает об ошибке;
одновременное сохранение из устаревшего окна отклоняется с 409.

Сохраняются только ID панелей, порядок, ширина, минимальная высота и revision.
Задач, паролей и источников в настройках нет. Запись атомарная, в отдельном каталоге
с правами 0700/0600; PostgreSQL, задачи и исходные доказательства не изменяются.
На новом VPS `/home/teamactivity/ui-state/layout.json`, в web — `/var/lib/activity-ui/layout.json`.
Каталог нужно включать в защищённый backup отдельно от БД.
Локальное демо использует отдельный gitignored `state/demo-ui`.

API: GET /api/layout для разрешённых панелей, PUT /api/layout только для admin.
PUT требует JSON, X-Activity-Action: save-layout и актуальный revision.
Нет CORS; cross-site запросы отклоняются. Подробности ролей: [ACCESS](ACCESS.md).

Код: src/layout-model.js, src/layout.js, src/main.js, activity/access.py, app.py.
Новых зависимостей нет. Существующие DOM-узлы сохраняются при перестановке;
фильтры, календарь и реестр продолжают работать.
