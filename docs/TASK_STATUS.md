# Ручное изменение статуса

Работает на действующем VPS; доступно только администратору.

В реестре владелец нажимает «Изменить», выбирает в карточке «Завершена» или «Открыта»,
при необходимости оставляет комментарий и нажимает «Сохранить статус».
После сохранения карточка и показатели перечитываются из PostgreSQL.
Для viewer и tech_lead запись запрещена сервером; скрытие кнопки не является защитой.

Решение создаёт событие completed или reopened с текущим временем, автором и
отдельным ручным evidence. Предыдущие события и исходные сообщения сохраняются.
Автор решения не становится исполнителем задачи. Исторические периоды не
переписываются: изменение действует с момента сохранения.

POST /api/tasks/{task_id}/status принимает status, expected_revision, request_id
(UUID) и необязательный reason. Личность берётся только из проверенного прокси.
Сервер проверяет роль admin, ACTIVITY_STATUS_WRITES=1, специальный заголовок
X-Activity-Action: change-status и происхождение запроса. Устаревшая версия
отклоняется с 409; повтор того же request_id не создаёт второе событие.
Решение проходит существующий proposals/review_log и транзакцию activity_writer.
Ручное evidence привязано к тенанту; Telegram-доказательства не подделываются.

Запись включена в действующем deploy/compose.trial.yaml через ACTIVITY_STATUS_WRITES.

Регрессионные проверки: tests/test_task_status.py, tests/test_access.py и frontend tests.
Живые задачи не менять только ради теста. SQL-проверки проводить в отдельной восстановленной БД.
